## Reminders

- Never delete sprint tasks. If changes are required, create a sub-sprint file (e.g., `sprint-02-A-updates.md`) and link to it.
- Always update sprint progress. Mark tasks as `[x]` for done, `[s]` for skipped, or `[u]` for updated in a sub-sprint.
- Always refer to the Source of Truth files. If confused, stuck, or considering a new approach, re-read the linked documents above.
- Focus on the planned design. Adhere strictly to the established plans and develop from the existing codebase.
- Implement real features, not placeholders. Break down large tasks into smaller, fully functional atomic tasks.
- Request review after each task. Announce task completion, state the next step, and always re-read these reminders before starting a new task.
